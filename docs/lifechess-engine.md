# Fairy-Stockfish в Chess with Life

Документ описывает интеграцию движка в Android-приложение и локальный
консольный адаптер. Правила партии находятся в
[`lifechess-rules.md`](lifechess-rules.md).

## Текущее устройство

Приложение использует существующую JNI-интеграцию `NativeStockfish` и вариант
`lifechess` в подмодуле `third_party/fairy-stockfish`. Поиск вызывается из
одного фонового executor, позиции передаются через FEN варианта вместе со
списком всех ходов от `searchRootFen`. `StateList` движка восстанавливается
проигрыванием истории; одинаковое смешивание ключей сохраняет распознавание
повторов, а контекст каждой партии изолирован в transposition table.

JNI-ответ содержит действие, UCI-ход, оценку, `scoreType`, перспективу,
`reason`, `gameId`, `requestId` и `stateRevision`. Java проверяет идентификаторы,
сверяет ход с `RuleEngine.legalActions()` и атомарно применяет одно типизированное
`GameAction`. Неизвестные/недоступные действия и устаревшие ответы не меняют
позицию. Отмена поиска адресуется `requestId`.

Действия движка: ход с конкретным превращением, `CLAIM_REPETITION`,
`CLAIM_FIFTY_MOVES`, `CLAIM_BARE_KINGS`, `OFFER_DRAW`, `ACCEPT_DRAW` и
`DECLINE_DRAW`. Служебное действие не переключает сторону и не прибавляет
полуход. Java-арбитр остаётся окончательной проверкой законности.

## Ничейные действия компьютера

Право человека заявить ничью проверяется правилами приложения; ни 50 ходов,
ни повторение, ни ровно два несоседних короля автоматически игру не завершают.
Для двух голых несоседних королей движок немедленно выбирает отдельное
`CLAIM_BARE_KINGS`: результат точен и не зависит от оценки.

Для прочих заявлений и принятия предложения используется общий C++-решатель.
Оценка `<= 0 cp` со стороны бота разрешает Claim/Accept; при положительной
оценке бот продолжает и отклоняет предложение. Если доступно несколько
заявлений, ответ указывает выбранную причину, не выводя её из оценки после
поиска. Предложение соглашения не посылается повторно в том же непобедительном
отрезке; его порог меняется от `-500 cp` в полном дебютном материале до `0 cp`
в эндшпиле. Предложение около порога ждёт завершения трёх итераций поиска;
существенно более плохая оценка (`250 cp` ниже порога) может дать раннее
предложение. Это поведение бота, не ограничение игрока. Аналитический режим
движка не инициирует ничейные действия.

Параметры приложения выбираются в одном окне настроек и сохраняются локально:
сторона игрока, бюджет поиска 1 000/2 000/5 000/10 000/25 000/50 000 узлов и
отображение оценки (по умолчанию выключено). Числа — бюджеты поиска, не рейтинги Elo.
Средний бюджет 10 000
  узлов совпадает с плейтестами. Отображаемая оценка подписана «за белых»,
показывает пешечный эквивалент и не является вероятностью победы или
результатом партии. Игровой поиск компьютера остаётся отдельным от оценки,
когда ход человека. Native-движок работает с одним потоком и таблицей
транспозиций 16 MiB; приложения не создают параллельные экземпляры движка.

## Контракт консольного адаптера

`tools/lifechess_console.py` принимает JSON Lines протокола версии 2.
Состояние включает `searchRootFen` и точный `searchMoves`, совпадающий со всеми
ходами из типизированной истории. Поиск запускается командой UCI
`position fen <root> moves ...`; это сохраняет историю повторов, счётчик
полуходов и контекст редакторской позиции. Ответ адаптера сохраняет `requestId`
и `stateRevision`. Fixture начальной позиции: `tools/fixtures/lifechess-initial.jsonl`.

Пример запуска после сборки движка:

```powershell
Get-Content .\tools\fixtures\lifechess-initial.jsonl |
  python .\tools\lifechess_console.py `
    --engine .\third_party\fairy-stockfish\src\stockfish.exe --depth 5
```

Запуск проверок Fairy-Stockfish и консольного контракта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\test-lifechess.ps1
```

При занятом `stockfish.exe` можно передать другое имя бинарника:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\test-lifechess.ps1 `
  -EngineExecutable lifechess-validation.exe
```

Android-проверки:

```powershell
$env:LIFECHESS_ENGINE = (Resolve-Path .\third_party\fairy-stockfish\src\stockfish.exe).Path
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug
```

В JNI/CMake задаются NDK 25.2.9519653, CMake 3.22.1 и ABI
`armeabi-v7a`, `arm64-v8a`, `x86`, `x86_64`. Для воспроизводимой проверки APK
нужны JDK 17, Android SDK API 35, требуемые NDK/CMake и свободный build-каталог.
Отсутствие этих средств означает пропуск сборки, а не успешную проверку.

## Статус проверки

Указывай здесь только результаты текущего прогона, а не прежние результаты.
Сборка консольного движка и Tcl/Python тесты не подтверждают JNI ABI, сборку
APK, установку на телефон или сценарии на устройстве. Отдельно фиксируй:

- фактически запущенные unit/parity и console/Tcl тесты и число тестов;
- успешность CMake/NDK сборки APK и ABI, включённые в APK;
- версию/ревизию движка и SHA-256 свежего артефакта;
- установку/запуск и сценарии, проверенные на устройстве;
- подпись release: использовать только настроенный ключ владельца; не создавать
  замену без отдельного решения владельца.
